# pstack 가이드

pstack은 에이전트를 세세하게 관리하지 않을 때 가장 잘 동작합니다. 여러분은 원하는 것과 완료되었는지 판단할 방법을 설명합니다. `/poteto-mode`가 플레이북을 고르고, 단계에 필요한 다른 스킬을 실행하고, 증거를 보여 줍니다. 이 가이드는 현실적인 프롬프트로 그 습관을 가르칩니다.

다음 내용을 배웁니다.

1. [pstack 설정하기](./01-setup.md). 플러그인을 설치하고 모델을 고릅니다.
2. [`/poteto-mode`로 작업 라우팅하기](./02-poteto-mode.md). 목표를 주고 플레이북을 고르는 과정을 지켜봅니다.
3. [코드 이해하기](./03-understand.md). 무엇이든 수정하기 전에 읽기 전용 조사를 하고, 그다음 `/how`, `/why`, `/teach`, `/recall`을 사용합니다.
4. [변경 설계하기](./04-design.md). 코드가 형태를 굳히기 전에 `/architect`, `/arena`, `/swarm`, `/interrogate`, 프로토타입, 계획을 활용합니다.
5. [변경을 구현하고 정리하기](./05-build-and-clean.md). 구현 플레이북, `/tdd`, `/unslop`, `/no-comments`를 다룹니다.
6. [검증하고 배포하기](./06-verify-and-ship.md). 실제 앱에서 동작을 증명하고, 테스트로는 거의 닿지 않는 부분을 형식 검증하고, `/benchmark-checklist`로 숫자를 점검한 뒤, 범위가 분명한 PR을 열어 병합될 때까지 진행합니다.
7. [자는 동안 작업 실행하기](./07-overnight.md). 루프보다 신뢰를 먼저 쌓는 법, 야간 작업 계약, 검토할 수 있는 결정 로그, 그리고 에이전트 하나를 넘어 확장되는 Projects와 자동화를 다룹니다.
8. [원칙 이름으로 방향 잡기](./08-principles.md). 작업 도중 에이전트의 방향을 바꾸는 24개의 이름을 다룹니다.
9. [나만의 방식으로 만들기](./09-make-it-yours.md). 나만의 모드, 반복되는 실수를 위한 `/correct`, 스킬 변경을 테스트하는 방법을 다룹니다.
10. [레시피와 함정](./10-recipes-and-pitfalls.md). 복사해 쓸 프롬프트와 피해야 할 실수를 다룹니다.

처음에는 페이지를 순서대로 읽으세요. 그 뒤로는 각 페이지를 따로 읽어도 됩니다.

막히거나 어떤 스킬이 맞는지 판단하기 어려울 때는 질문과 함께 [`/poteto-help`](../../skills/poteto-help/SKILL.md)를 입력하세요.

```text
/poteto-help 이 브랜치를 리뷰하려면 어떤 스킬을 써야 해?
```

`/poteto-help`는 답을 주고, 보낼 프롬프트를 건네고, 답의 출처가 된 스킬이나 가이드 페이지를 링크합니다. pstack 실행은 실제로 토큰을 소비하기 때문에 작업을 직접 시작하지 않으며, 여러분이 준비되었을 때 프롬프트를 보내면 됩니다. 여러분이 입력할 때만 실행됩니다.

## 딱 하나만 기억한다면

에이전트에게 목표와 그것을 확인할 방법을 여러분의 말로 주세요.

```text
/poteto-mode 실행 도중에 재시도가 끼어들면 내보내기가 중복 행을 써. 먼저 재현하고, 그다음 고치고 검증해 줘.
```

플레이북 이름을 대거나 스킬을 나열할 필요가 없습니다. "먼저 재현하고"라는 말과 확인 가능한 결과만 있으면 `/poteto-mode`가 라우팅하는 데 충분합니다. `/poteto-mode`는 Bug fix 플레이북을 고르고, 그 단계를 할 일 목록으로 옮긴 뒤, 각 단계가 실행될 때 알맞은 스킬을 호출합니다.
