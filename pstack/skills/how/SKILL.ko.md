# How

코드베이스를 탐색하여 "X는 어떻게 동작하나요?"라는 질문에 답합니다. 하위 시스템에 온보딩하는 시니어 엔지니어 수준으로 아키텍처를 설명합니다. 동작하는 멘탈 모델을 세우기에 충분해야 하지만, 주석을 단 소스 코드처럼 읽힐 정도로 자세해서는 안 됩니다.

모든 생성(spawn)은 `subagent_type: generalPurpose`와 `readonly: true`를 지정한 Task 서브에이전트입니다. 탐색자(explorer)는 `pstack-models.mdc` 규칙의 `how explorer` 줄(기본값 `grok-4.7-xhigh-fast`)을 사용하고, 모든 설명자(explainer)는 `how explainer` 줄(기본값 `claude-opus-5-5-xhigh`)을 사용합니다. `model`은 해당 줄의 값으로 설정하고, 규칙이나 해당 줄이 없으면 기본값으로 설정합니다. 값이 `auto` 또는 `inherit-parent`이면 `model`을 설정하지 않습니다. Task 도구가 슬러그를 거부하면 기본값을 사용하고 그 사실을 알립니다. 기본값도 거부하면 오류 메시지에 나온 슬러그 중 같은 계열에서 가장 가까운 유효한 슬러그를 사용합니다. 각 서브에이전트의 추론 수준과 빠른 속도 또는 표준 속도는 **poteto-mode** 스킬의 Subagents 섹션에 따라 작업에 맞게 고릅니다.

## 1. 복잡도 평가

범위가 모호하면 자신의 해석을 밝히고 탐색합니다. 사용자가 방향을 바로잡을 수 있습니다.

- **단순함** (단일 모듈, 작은 유틸리티, "함수 X는 어떻게 동작하나요" 같은 좁은 질문): 탐색자를 쓰지 않습니다. 탐색과 설명을 한 번에 수행하는 설명자 하나를 생성합니다. 이 설명자의 프롬프트는 `references/explainer-prompt.md`에서 탐색자 결과 섹션을 뺀 채로 만듭니다. 4단계로 갑니다.
- **복잡함** (여러 파일이나 서비스에 걸친 하위 시스템, 여러 영역을 가로지르는 기능, 전체 아키텍처 개요): 2단계로 갑니다.

확신이 서지 않으면 단순한 경로를 택합니다.

## 2. 탐색 (복잡한 경우에만)

질문을 2개에서 4개의 관점으로 나눕니다. 각 관점은 하위 시스템에서 서로 구별되는 한 부분입니다. 모든 탐색자를 하나의 메시지에서 생성하고, 각 탐색자에게 `references/explorer-prompt.md`를 해당 관점으로 채워서 줍니다.

## 3. 종합 (복잡한 경우에만)

모든 탐색자가 결과를 반환하면, `references/explainer-prompt.md`에 모든 탐색자의 결과를 채워 넣어 설명자 하나를 생성합니다.

## 4. 제시

설명자의 출력을 제시합니다. 명확성을 위해 가볍게 다듬거나 대화 맥락을 덧붙이는 것은 괜찮습니다. 내용을 크게 다시 쓰지 않습니다.

## 출력 형식

설명은 `references/explainer-prompt.md`에 정의된 섹션을 사용하고, 해당하지 않는 섹션은 뺍니다. 섹션은 Overview, Key Concepts, How It Works, Where Things Live, Gotchas입니다.
