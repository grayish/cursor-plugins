# 더하기 전에 빼기

시스템을 발전시킬 때는 먼저 복잡도를 제거한 뒤에 만듭니다. 기본값은 빼는 것입니다.

단순화를 꾸준한 투자로 삼습니다. 처음 발견했을 때와 같거나 더 작은 겉면 뒤에서, 설계를 조금 더 단순하고 조금 더 유능한 상태로 남겨 둡니다.

- 만들기보다 제거를 먼저 하도록 순서를 정합니다
- 다듬기 전에 잘라냅니다(품질에 투자하기 전에 최소한의 형태에 먼저 도달합니다)
- 추측한 예외 상황이 아니라 실제로 관찰한 사용 방식에 맞춰 설계합니다
- 명세가 요구하는 수준을 넘어서는 추측성 검증기, 파서, 가드를 두지 않습니다
- 프롬프트를 단순화합니다(중복된 지시, 과도한 템플릿을 제거합니다)
- 참조에 새로운 내용이 없다면 내용 없는 껍데기로 남기지 말고 삭제합니다
