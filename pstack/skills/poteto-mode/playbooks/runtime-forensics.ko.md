### 런타임 포렌식

**진단의 책임은 당신에게 있습니다. 소스만 보고 이론을 세우지 말고 실행 중인 프로세스를 계측하세요.** 결과물은 수정이 아니라 근거를 인용한 진단입니다.

1. control 스킬로 해당하는 표면에서 실시간 신호를 수집합니다. CPU를 계속 점유하는 프로세스라면 CPU 프로파일, 메모리 누수라면 힙 스냅샷, 시각적 결함이라면 CDP 트레이스를 수집합니다. 추측이 아니라 실제 산출물이어야 합니다.
2. 산출물을 결정적 증거로 좁힙니다. 핫 패스에 있는 함수, 누수된 객체에서 GC 루트까지 이어지는 retainer 체인, 입력 없이 계속 실행되는 루프가 그런 증거입니다. 큰 산출물은 서브에이전트에서 파싱하고(**guard-the-context-window** 원칙 스킬), 좁혀진 결과만 메인 스레드에 남깁니다. Subagents 섹션에 따라 각 서브에이전트의 추론 수준과 fast 또는 standard 속도를 작업에 맞게 고릅니다.
3. 메커니즘을 믿기 전에 증명합니다. 실행 중인 프로세스에 CDP eval로 계측 코드를 주입하거나, 다시 로드하지 않고 실행 중인 코드를 핫픽스하여 적은 비용으로 가설을 확인합니다.
4. 발견한 내용을 소스에 연결합니다. 파일, 심볼, 메모리를 할당하거나 작업을 예약하는 줄을 찾습니다.
5. 처리량 체크포인트는 한 줄로 유지합니다. `throughput checkpoint: n/a, read-only forensics`

**응답:** 수집한 신호, 좁혀진 결과, 메커니즘을 증명한 방법, 소스 위치, 산출물 경로를 알립니다. 요청받지 않았다면 수정하지 않습니다. 원인이 밝혀지면 Bug fix나 Perf로 넘깁니다.
