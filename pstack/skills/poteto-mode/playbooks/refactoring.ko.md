### 리팩터링

**계약(contract)을 지키는 책임은 당신에게 있습니다. 구조는 바뀌고, 동작은 바뀌지 않습니다.** 동작을 추가하는 Feature, 동작을 바로잡는 Bug fix와는 구별됩니다.

정리하다가 빠진 기능이나 실제 버그가 드러나면 그것을 따로 분리하고, 고정해 둔 계약을 기준으로 구조 변경을 먼저 배포합니다. 재설계도 허용되지만, 재설계라고 명시하고 Feature로 넘깁니다. 규모가 크거나 여러 영역에 걸친 구조 작업은 **figure-it-out** 스킬이 담당합니다. 이 플레이북은 범위가 좁거나 중간 규모인 변경을 다룹니다.

1. 동작 계약을 먼저 고정합니다. 영향을 받는 하위 시스템에 **how** 스킬을 실행해 계약을 파악한 다음, 구조를 건드리기 전에 현재 동작을 담아내는 특성 테스트(characterization test), 스냅샷, 또는 동등성 하네스를 작성합니다. 해당 영역에 테스트 커버리지가 없다면 구조를 건드리기 전에 고정 장치부터 작성합니다. 타입 체크와 린트는 고정 장치가 아닙니다.
2. **principle-model-the-domain**에 따라 코드에 빠져 있는 구조를 명시합니다. 형태가 이미 명확하고 국소적이라면 단순한 코드는 그대로 둡니다. 구조를 바꾸면 분기나 잘못된 상태가 사라져야 하며, 간접 계층이 늘어나서는 안 됩니다.
3. 목표 형태를 명시합니다. 오늘 새로 만든다면 모듈 구성, 타입, 호출 그래프가 어떠해야 하는지 적습니다(**principle-foundational-thinking**, **principle-redesign-from-first-principles**). 목표가 함수 경계를 넘는다면, 옮기기 전에 **architect** 스킬을 실행해 형태에 대한 병렬 설계 탐색을 합니다.
4. 더하기 전에 뺍니다. 새 형태를 도입하기 전에 죽은 코드를 삭제하고, 호출자가 하나뿐인 래퍼를 합치고, 중복된 검증기를 없애고, 고아가 된 참조를 제거합니다(**principle-subtract-before-you-add**). 목표 형태에 도달하는 가장 작은 변경을 배포합니다(**principle-laziness-protocol**). "도움이 될지도 모르는" 추측성 정리는 되돌립니다.
5. 동작을 보존하는 작은 단계로 옮기고, 매 단계에서 고정 장치가 통과 상태를 유지하게 합니다. API 형태를 바꿀 때는 모든 호출자를 마이그레이션하고 같은 단계에서 기존 API를 삭제합니다(**principle-migrate-callers-then-delete-legacy-apis**). 호환성 shim을 두지 않고, 기존 경로와 새 경로를 병행하지 않습니다. 모든 이름 변경은 실제 파일을 대상으로 직접 확인합니다. 이름 변경은 문자열, 설명 글, 역참조에 있는 사용처를 조용히 놓치기 쉽습니다. 기계적인 수정은 설정해 둔 refactoring 모델(기본값 `grok-4.7-xhigh-fast`)을 사용하는 서브에이전트에 구체적인 범위(파일 경로, 옮길 이름, 유지해야 할 동작)와 함께 위임합니다. Subagents 섹션에 따라 각 서브에이전트의 추론 수준과 fast 또는 standard 속도를 작업에 맞게 고릅니다.
6. "컴파일된다"가 아니라 실제 산출물에서 동작이 바뀌지 않았음을 증명합니다(**principle-prove-it-works**). 규모가 큰 구조 변경이라면 동등성 검사를 실행합니다. 이전 출력과 새 출력을 diff하는 스크립트, 기록해 둔 기준선을 새 코드에 재생하는 방법, 또는 관련 control 스킬로 해당 표면에서 실행하는 스모크 테스트를 사용할 수 있습니다.
7. 변경을 유지할 가치가 있는지 확인합니다. 성공의 척도는 읽는 사람의 부담이 줄었는지입니다(**principle-minimize-reader-load**). diff가 어디에서도 읽는 사람의 부담을 줄이지 못한다면 되돌립니다.
8. 작고 순서가 정해진 커밋으로 리베이스합니다. 먼저 삭제 커밋, 다음으로 구조 변경 커밋, 그다음 후속 정리 커밋 순서로 둡니다. **sequence-verifiable-units** 원칙 스킬로 커밋을 구성하여, 동작을 보존하는 각 조각이 다음 조각으로 넘어가기 전에 통과 상태를 유지하게 합니다. **Opening a PR**을 실행합니다.

**응답:** 바뀐 구조, 기준으로 삼은 고정 장치, 동등성 증명, 읽는 사람의 부담 변화량, 배포한 것과 되돌린 것을 알립니다. 새로운 동작은 없어야 합니다.
