# 동작함을 증명하기

모든 작업 결과는 실제 대상을 직접 확인해서 검증합니다. 대리 지표, 자기 보고, "컴파일은 된다"로부터 추론하지 않습니다.

**이유:** 검증하지 않은 작업은 정확한지 알 수 없습니다. 간접 검증(파일 수정 시각, 출력이 최신인지 여부, 에이전트의 자기 보고, 캐시된 스크린샷)은 직접 관찰보다 비용이 적어 보입니다. 하지만 잘못된 추론에 따라 행동하는 비용은 원본을 확인하는 비용보다 훨씬 큽니다.

대리 지표가 아니라 실제 대상을 확인합니다.
- 프로세스가 살아 있는지는 파생된 상태로 간접 확인하지 말고 직접 확인합니다
- 캐시되었거나 파생된 표현이 아니라 실제 값을 읽습니다
- 검증이 실패하면 시스템을 의심하기 전에 관찰 방법부터 의심합니다

## 가능하면 검사를 스크립트로 만들기

가장 강력한 증명은 한 번 눈으로 확인하는 것이 아니라, 같은 비교를 다시 실행하는 결정적(deterministic) 스크립트입니다. 스크립트를 작성하고 실행한 뒤, 리뷰어가 여러분의 말을 믿는 대신 직접 다시 실행해 볼 수 있도록 그 출력을 결과물로 남깁니다.

이 결과물은 사람(사용자)이 볼 수 있게 둡니다. 큰 포팅이나 마이그레이션처럼 나중에 작업 이력을 감사할 수 있어야 하는 크고 복잡한 작업에서만 커밋합니다(**show-me-your-work** 스킬).
