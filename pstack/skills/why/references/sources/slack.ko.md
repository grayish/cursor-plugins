# Slack 대화

## 검색 방법

Slack MCP 도구는 환경마다 다릅니다. 먼저 어떤 Slack MCP를 사용할 수 있는지 확인하고 도구 스키마를 살펴봅니다. `mcp_auth`가 필요할 수 있습니다. 인증에 실패하면 중단하고 공백을 보고합니다.

1. **작성자로 범위를 한정한 검색.** PR 머지 날짜 전후에 PR 작성자가 보낸 메시지를 찾습니다. 범위가 크게 줄어들고, 결정적인 단서를 찾는 경우가 많습니다.
3. **PR URL 검색.** Slack에서는 PR을 리뷰하거나 논의할 때 PR 링크를 공유하는 경우가 많습니다. PR URL(또는 `/pull/<number>`만)로 검색합니다.
4. **오류 문자열 검색.** 코드가 특정 오류를 처리한다면 그 오류 문자열로 검색합니다. 장애 대응 스레드가 나오는 경우가 많습니다.

## 흔한 함정

- **채널 기록 탐색의 한계.** 아주 오래된 메시지는 보존 정책 때문에 삭제되었을 수 있습니다. 특정 날짜 이전으로는 아무것도 찾을 수 없다면 보존 기간의 경계를 기록합니다.
- **검색되지 않는 DM.** 많은 결정이 검색할 수 없는 DM에서 이루어집니다. 이런 결정은 놓치게 됩니다. 이것은 알려진 한계입니다.
- **농담 섞인 추측을 "결정"으로 오해하는 경우.** Slack은 격식 없는 공간입니다. "ㅋㅋ 그냥 그거 하세요"는 커밋 직전에 나온 말이라도 결정이 아닙니다. 충분히 검토한 논의를 찾습니다.
- **단일 메시지에서 맥락이 사라지는 문제.** 스레드 없이 메시지 하나만 보면 맥락 안에서 읽을 때와 다르게 읽히는 경우가 많습니다. 항상 스레드를 가져옵니다.
- **인증 실패.** MCP가 인증되지 않았다면 중단합니다. 결과를 지어내지 않습니다. Slack을 검색할 수 없었다고 보고합니다.
