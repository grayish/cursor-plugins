# Notes 검증 맵

> 이 문서는 [README.md](./README.md)를 한국어로 번역한 문서입니다. 원본과 내용이 다르면 원본을 기준으로 합니다.

이 디렉터리는 Notes에서 사용자에게 보이는 동작을 검증하기 위해 관리하는 기준 자료입니다. 앱을 조작하기 전에 색인을 읽고, 해당하는 기능 파일을 절차서로 사용합니다.

## 기본 사전 조건

- 일회용 데이터 디렉터리를 사용해 `http://127.0.0.1:4173`에서 Notes를 실행합니다.
- 동시에 실행되는 작업끼리 상태를 공유하지 않도록 `NOTES_DATA_DIR=/tmp/notes-verify-$RUN_ID`를 설정합니다.
- 제목이 `Quarterly plan`과 `Grocery list`인 노트를 미리 넣어 둡니다.
- `control-notes`와 `notes` CLI를 `PATH`에 추가합니다.
- `control-notes doctor`를 실행하고, 예상한 URL, 데이터 디렉터리, 빌드 리비전이 나오는지 확인합니다.
- 이번 검증 실행에서 시작하지 않은 인스턴스는 절대 조작하지 않습니다.

## 조작 규칙

- 사전 조건에서 따로 정하지 않는 한 모든 절차는 기본 상태에서 시작합니다.
- CSS 선택자나 DOM 위치보다 ARIA 역할과 접근 가능한 이름을 우선 사용합니다.
- 모든 명령어는 적힌 그대로 사용합니다. 따옴표로 묶인 이름과 플래그를 바꾸지 않습니다.
- 브라우저 동작은 `control-notes browser`로 실행합니다.
- 터미널 동작은 `control-notes cli -- <command>`로 실행합니다.
- 데이터를 변경한 뒤에는 미리 넣어 둔 데이터를 복원합니다. 정리 과정에서 증거 산출물을 삭제하지 않습니다.

## 증거 및 건너뜀 보고

- 최종 화면만이 아니라 사용자 동작과 그 결과 상태를 함께 캡처합니다.
- UI 증거에는 ARIA 스냅샷과, 앱 정체가 보이는 스크린샷이 포함됩니다.
- CLI 증거에는 명령어, stdout, stderr, 종료 코드가 포함됩니다.
- 데이터 변경 증거에는 저장된 값을 읽기 전용으로 보여 주는 두 번째 화면이 포함됩니다.
- 모든 산출물에 사용한 기능 ID와 진입점을 기록합니다.
- 도달할 수 없는 경로는 시도한 명령어와 충족되지 않은 사전 조건을 함께 보고합니다.
- 건너뛴 진입점을 다른 경로로 검증했다고 보고하지 않습니다.

## 기능 항목 형식

각 기능 파일은 H1 제목과, 사용자에게 보이는 동작을 설명하는 단락 하나로 시작합니다. 그다음 정확히 네 개의 H2 섹션을 다음 순서대로 사용합니다.

1. `Sub-features`는 동작마다 한 줄씩 짧은 ID를 나열합니다.
2. `How to get to it (user POV)`는 사용자 진입점을 모두 나열합니다.
3. `Driving it with <harness>`는 `Preconditions:`로 시작하고, 각 사용자 동작을 정확한 명령어 및 관찰 가능한 결과와 짝지은 레이블 목록을 사용합니다.
4. `Gotchas`는 검증 실행을 낭비하게 하거나 무효로 만들 수 있는 함정을 나열합니다.

맵에는 구현 세부 사항을 넣지 않습니다. 사용자 경로, 안정적인 핸들, 필요한 상태, 명령어, 관찰 가능한 증거만 적습니다.

## 기능

- [노트 만들기](./create-note.md)는 브라우저와 CLI에서의 생성, 취소, 저장 유지, 정리를 다룹니다.
- [노트 검색](./search.md)은 툴바, 키보드, CLI 검색과 일치, 빈 결과, 초기화 상태를 다룹니다.
