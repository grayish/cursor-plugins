# 숫자를 설명하기

- **"왜 두 배가 아닌가?"를 묻습니다.** 결과를 제한하는 자원이나 코드 경로를 명시합니다. 예를 들어 코어, 락, 디스크, 네트워크, 또는 부하 생성기 자체가 해당합니다. 이 제한 요인은 실행 중에 수집한 프로파일이나 시스템 카운터에서 찾은 뒤 소스 코드와 연결합니다. 코드를 읽고 짐작한 것은 제한 요인이 아닙니다. 숫자가 왜 두 배로 좋지 않은지 말할 수 없다면, 무엇을 측정했는지 모르는 것입니다.
- **그 숫자가 달리 무엇을 측정하고 있을 수 있는지 나열하고, 각각을 증거로 배제합니다.** 흔한 용의자는 오류, 건너뛰었거나 캐시된 작업, 실행되지 않은 코드, 튜닝하지 않은 한쪽(기본 설정으로 남겨 둔 쪽), 노이즈, 그리고 전체 흐름에서는 의미가 없을 만큼 작은 부분입니다.
- **증거를 숫자와 함께 보관합니다.** 실행 횟수, 편차, 제한 요인을 노트나 연결된 결과물에 기록합니다.

성능 숫자라면 [benchmark-checklist](../benchmark-checklist/SKILL.md) 스킬로 전체 절차를 수행합니다. 평가(eval) 결과라면 시행(trial)에 대해서도 같은 질문을 합니다. 모든 실행이 과제를 수행했는지, 차이가 여러 시행과 여러 모델에서 유지되는지, 시나리오가 의미 있는지 확인합니다.

숫자를 뒷받침하는 증거에 실행 횟수, 편차, 명시된 제한 요인 중 하나라도 없거나, 절약한 시간이 변경한 부분이 원래 차지하던 시간보다 크다면 이 원칙을 건너뛴 것입니다.
