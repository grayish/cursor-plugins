# 결과 중심 실행

매끄러운 중간 상태를 유지하는 것보다 의도한, 검증 가능한 최종 상태에 맞춰 최적화합니다.

**이유:** 모든 중간 단계를 완전히 안정적으로 유지하려 하면 임시 호환성 코드가 생기기 쉽고, 이 코드는 오래 남는 부채가 됩니다. 목표 아키텍처로 수렴하고, 명시적인 검증 경계에서 정확성을 증명합니다.

**핵심 규칙:**
- 전환 과정의 안정성보다 최종 상태의 무결성을 우선합니다
- 중간에 깨지는 것은 계획되어 있고, 범위가 정해져 있고, 되돌릴 수 있다면 허용됩니다

**안전장치:**
- 단계 경계가 명시된 계획된 재작성과 마이그레이션에 사용합니다
- 일시적으로 깨져도 되는 곳을 미리 선언합니다
- 마이그레이션하는 동안 실제로 손대는 영역에는 신호가 강한 검사를 유지합니다
- 계획을 마칠 때 정적 검증과 런타임 검증을 모두 완전히 수행해야 합니다
