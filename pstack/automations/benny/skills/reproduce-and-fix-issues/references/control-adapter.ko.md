# Control-adapter 계약

> 이 문서는 [control-adapter.md](./control-adapter.md)를 한국어로 번역한 문서입니다. 원본과 내용이 다르면 원본을 기준으로 합니다.

Benny는 모든 앱을 시작하거나 조작하는 방법을 알지 못합니다. 사용자는 대상 앱에 대해 이 계약을 구현하는 control 스킬이나 adapter를 하나 구성해야 합니다.

그 스킬 이름을 `control.skill_name`에 설정합니다.

완성된 사용자 관점 feature map 경로를 `control.feature_map_path`에 설정합니다. 복사해 온 예시를 직접 수정하지 말고, [`feature-map.example.md`](./feature-map.example.md)를 `.cursor/automations/benny/` 바깥에 복사한 뒤 내용을 채웁니다.

스킬, feature map, 필수 기능 중 하나라도 없거나, 모호하거나, 불완전하면 재현 및 수정 작업은 안전하게 실패(fail closed)해야 합니다.

## 필수 기능

### 시작(Bring up)

요청된 앱 리비전을 요청된 테스트 환경에서 시작합니다.

입력:

- 저장소와 리비전
- 빌드 또는 시작 모드
- 워크스페이스, 계정, fixture, 기능 상태 요구 사항
- 아티팩트 디렉터리
- 완성된 feature map 경로

반환:

- 세션 식별자
- adapter가 올바른 앱과 환경임을 확인한 방법
- 안정적인 앱 마커
- 이후 호출에 필요한 실행 중인 프로세스 또는 대상 정보
- 누락된 기능

adapter는 대상 앱을 비슷한 창, 셸, 프로덕션 인스턴스와 구별해야 합니다.

### UI 조작

실제 사용자 동작을 수행합니다.

- 클릭
- 입력
- 키 누르기
- 스크롤
- 드래그
- 크기 조정
- 앱 컨트롤을 통한 탐색

role, label, 안정적인 selector를 우선 사용합니다. 좌표는 새 스크린샷을 찍은 뒤에만 사용합니다.

각 동작과 관찰된 상태 변화를 반환합니다.

증상을 만들기 위해 내부 상태를 설정하거나, 숨겨진 앱 메서드를 호출하거나, 저장소에 직접 쓰거나, DOM 변경을 주입하지 않습니다.

### 매핑된 기능과 상태 조작

앱을 조작하기 전에 관련 feature map 섹션을 읽습니다.

adapter는 다음을 수행할 수 있는 방법을 제공해야 합니다.

- 매핑된 모든 기능을 사용자에게 보이는 경로로 탐색합니다.
- 해당 기능에 나열된 adapter 동작 이름을 호출합니다.
- 해당되는 경우 default, hover, focus-visible, active, disabled, loading, empty, error, selected, open, expanded 상태와 기능별 상태를 다룹니다.
- 안전한 fixture 데이터, 권한, 플래그, 서비스 응답, 지원되는 테스트 컨트롤을 통해 상태를 준비합니다.
- 두 번째 독립 재현 시도를 위해 기능을 초기화합니다.
- feature map에 지정된 스크린샷, 동영상, 읽기 전용 교차 확인을 캡처합니다.

role, 접근 가능한 이름(accessible name), ARIA 관계, 안정적인 컴포넌트 마커, 목적이 드러나는 이름의 data 속성을 사용합니다. 생성된 CSS 또는 StyleX 클래스, 동적 해시, 자식 인덱스, 깨지기 쉬운 DOM 위치는 절대 사용하지 않습니다.

전제 조건을 준비하는 것이 보고된 증상을 주입해도 된다는 뜻은 아닙니다. 재현 자체는 여전히 실제 사용자 상호작용에서 나와야 합니다.

### 상태 검사

UI에 표시된 내용을 확인하기 위해 상태를 읽습니다.

예:

- 접근성 트리
- DOM 또는 뷰 계층
- 프로세스 상태
- 로컬 로그
- 네트워크 요청 상태
- 앱이 노출하는 디버그 상태

검사는 읽기 전용입니다. 조회가 상태를 바꾼다면 그 조회는 `drive UI`에 속하며 실제 사용자 동작을 나타내야 합니다.

### 스크린샷

현재 앱 상태를 요청된 경로에 캡처합니다.

반환:

- 파일 경로
- 캡처 시각
- 앱 마커 또는 창 제목
- 화면에 보여야 할 내용에 대한 짧은 설명

스크린샷에는 올바른 앱을 테스트하고 있음을 증명할 만큼 앱의 외곽 UI(chrome)가 충분히 보여야 합니다.

### 녹화

전체 재현 경로 앞뒤로 화면 녹화를 시작하고 중지합니다.

반환:

- 파일 경로
- 시작 및 중지 시각
- 캡처한 창 또는 영역
- 오디오나 민감한 오버레이를 제외했는지 여부

녹화에는 준비 과정이나 로딩 화면뿐 아니라 결과를 판별할 수 있는 최종 상태가 보여야 합니다.

### 정리

adapter가 만든 프로세스와 세션을 중지합니다.

다음과 같은 일회용 항목을 제거합니다.

- 브라우저 또는 앱 프로필
- 임시 워크스페이스
- adapter가 만든 테스트 계정 또는 fixture
- 디버그 포트와 터널
- 보존 기간이 지난 캡처

무엇을 중지했고, 제거했고, 보존했고, 사람(사용자)에게 남겼는지 반환합니다.

정리 과정에서 사용자 작업을 삭제해서는 안 됩니다.

## Adapter 동작

adapter는 다음을 지켜야 합니다.

- 재현을 시작하기 전에 기능을 보고합니다.
- 어떤 feature map 섹션을 조작할 수 있고 어떤 섹션이 막혀 있는지 보고합니다.
- 기준 빌드와 패치된 빌드에 같은 환경 입력을 사용합니다.
- 시작 실패를 실패로 드러냅니다.
- 재시도 횟수를 제한합니다.
- 로그와 아티팩트에 비밀 정보가 들어가지 않게 합니다.
- 캡처를 저장소 바깥에 보관합니다.
- 두 번의 재현 시도 사이에 새 상태 또는 초기화된 상태를 지원합니다.
- 사용자가 안전한 테스트 동작을 명시적으로 구성하지 않았다면 프로덕션 변경을 피합니다.

## 환경 변환

환경 때문에 막혔다고 선언하기 전에, 플랫폼에 특화된 명사를 빼고 결함을 다시 서술한 뒤 사용 가능한 환경에서 같은 동작을 안전하게 테스트할 수 있는지 따져 봅니다.

예:

- 특정 브라우저 이름은 임의의 외부 브라우저를 뜻할 수 있습니다.
- 특정 키 이름은 구성된 단축키를 뜻할 수 있습니다.
- 특정 원격 호스트 이름은 지연되거나 연결이 끊긴 원격 대상을 뜻할 수 있습니다.

변환한 시도는 같은 근본 동작을 테스트할 때만 사용합니다. 그 시도는 변환된 증거로 표시합니다. 누락된 환경이 결함의 일부라면 그 시도를 정확한 재현이라고 부르지 않습니다.

하드웨어 프롬프트, 운영체제 권한 대화상자, 기기 전용 API, 사용할 수 없는 계정 상태는 실제로 막힌 경우일 수 있습니다.

## 설정 확인

재현 자동화를 활성화하기 전에 해가 없는 adapter 확인을 한 번 실행합니다.

1. 앱을 시작합니다.
2. 안정적인 앱 마커를 확인합니다.
3. 완성된 feature map 섹션 하나를 불러옵니다.
4. 해당 기능의 사용자 경로를 따라 그 기능으로 이동합니다.
5. 매핑된 adapter 동작으로 일회용 상태 하나를 직접 다뤄 봅니다.
6. 그 결과 상태를 검사합니다.
7. 스크린샷을 캡처합니다.
8. 짧은 클립을 녹화합니다.
9. 정리합니다.

아홉 단계가 모두 성공하고 출처 채널의 Slack 게시물이 관련되지 않은 경우에만 재현 작업을 활성화합니다.
