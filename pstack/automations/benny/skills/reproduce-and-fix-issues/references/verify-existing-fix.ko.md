# 기존 수정 검증하기

> 이 문서는 [verify-existing-fix.md](./verify-existing-fix.md)를 한국어로 번역한 문서입니다. 원본과 내용이 다르면 원본을 기준으로 합니다.

열린 PR이나 머지된 커밋이 보고된 문제를 수정했을 가능성이 있을 때 이 모드를 사용합니다.

수정은 기존 산출물이 담당합니다. 그 산출물을 검증합니다. 산출물을 편집하거나, 경쟁하는 패치를 작성하거나, 다른 PR을 열지 않습니다.

## 산출물 자격 확인하기

구체적인 산출물 하나가 반드시 있어야 합니다.

- 증상을 해결하는 코드 변경이 포함된 열린 PR
- 머지된 PR
- 코드와 의도가 일치하는 머지된 커밋

PR이나 커밋 없이 스레드에서 한 주장, 트래커 상태, 브랜치 이름, 원인 가설만 있다면 충분하지 않습니다.

산출물이 여러 개 있으면 소스 스레드나 트래커에서 링크된 산출물을 선택합니다. 그렇지 않으면 영향받는 코드와 가장 가깝게 일치하는 산출물을 선택하고 그 이유를 밝힙니다.

## 작업 트리 보호하기

저장소가 지원하면 격리된 워크트리나 다른 깨끗한 체크아웃을 사용합니다. 사용자의 변경 사항을 덮어쓰지 않습니다.

다음을 기록합니다.

- 기준(baseline) 리비전
- 패치된 리비전
- PR 또는 커밋 URL
- 두 실행이 공유하는 빌드 및 환경 입력

일반 `github.com` PR 링크를 사용합니다.

## 기준 측정하기

열린 PR이라면 그 PR의 베이스 브랜치를 기준으로 사용합니다.

머지된 수정이라면 수정 직전 리비전이 빌드되고 이전 동작을 나타낼 때 그 리비전을 사용합니다.

설정된 제어 어댑터를 통해 다음을 수행합니다.

1. 기준 앱을 실행합니다.
2. 올바른 앱과 환경인지 확인합니다.
3. 실제 UI 동작으로 보고된 경로를 실행합니다.
4. 문제를 판별하는 증상을 관찰합니다.
5. 초기화한 뒤 다시 반복합니다.
6. 기준 녹화, 스크린샷, 상태 확인 결과를 캡처합니다.

기준에서 증상이 두 번 나타나지 않으면 기준이 없는 것입니다. 수정이 동작한다고 주장하지 않습니다.

## 패치된 빌드 측정하기

동일한 환경과 데이터로 PR 또는 수정 커밋을 빌드하고 실행합니다.

1. 같은 UI 경로를 실행합니다.
2. 두 번 반복합니다.
3. 깨진 상태가 사라졌는지 확인합니다.
4. 기대한 상태가 나타나는지 확인합니다.
5. 수정 후 녹화, 스크린샷, 동일한 상태 확인 결과를 캡처합니다.

컴파일이나 테스트에서 멈추지 않습니다. 수정 후 결과는 실행 중인 패치된 앱에서 나와야 합니다.

## 결과

### 확인됨

기준에서 두 번 재현되고 패치된 빌드에서 두 번 해결됩니다.

- 운영 상태를 검증됨으로 표시합니다.
- 산출물을 링크합니다.
- 소스 사전 점검 후 소스 스레드에 간결한 답글을 하나 게시합니다.
- 수정 전과 수정 후 결과를 포함합니다.
- PR을 열지 않습니다.

### 불충분한 수정

기준 빌드와 패치된 빌드 모두에서 증상이 나타납니다.

- 운영 상태를 재현되었으나 수정되지 않음으로 표시합니다.
- 산출물을 링크하고 그 산출물이 증상을 해결하지 못했다고 밝힙니다.
- 이번 실행에서 아직 사용하지 않았다면 일반적인 재현 확인 소스 업데이트를 게시합니다.
- 경쟁하는 PR을 열지 않습니다.

### 결론 없음

기준이 재현되지 않거나, 패치된 앱을 실행할 수 없거나, 증거가 판별 상태를 보여 주지 않습니다.

- 성공을 주장하지 않습니다.
- 기준과 패치된 빌드 중 어느 쪽을 측정할 수 없었는지 밝힙니다.
- 결과는 운영 스레드나 실행 출력에 남겨 둡니다.
- 직접적인 질문에 답해야 하는 경우가 아니면 소스 스레드에 아무것도 게시하지 않습니다.

## 정리

두 빌드를 모두 중지하고, 보존 정책에 따라 임시 프로필과 캡처를 제거하고, 사용자 작업을 버리지 않으면서 저장소를 이전 상태로 되돌립니다.
