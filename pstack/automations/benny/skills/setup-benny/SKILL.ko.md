# Benny 설정하기

Benny는 pstack 안에 비활성 상태의 자동화 팩으로 포함되어 배포됩니다. 플러그인 매니페스트는 pstack의 일반 스킬 루트만 노출합니다. 이 파일과 두 운영 파일은 슬래시 스킬이 아닙니다.

사람(사용자)은 Cursor가 팩의 `FOR_AGENTS.md`를 가리키게 하는 방식으로 설정을 시작합니다. 부트스트랩 흐름은 팩 전체를 대상 저장소로 복사한 다음, `.cursor/automations/benny/skills/setup-benny/SKILL.md`에 있는 이 파일을 직접 읽습니다.

Benny에는 외부 구성과 실제로 동작하는 Cursor 자동화 두 개가 필요합니다.

사용자가 명시적으로 요청하기 전에는 자동화를 생성하거나 업데이트하지 않습니다. 비밀 값을 플러그인 파일, 프롬프트, 커밋된 구성에 절대 넣지 않습니다.

## 1. 팩을 복사하고 공유 pstack 스킬을 활성화하기

Benny 구성을 묻기 전에, 그리고 내장 `/automate` 스킬을 호출하기 전에 이 단계를 수행합니다.

어느 저장소에서 자동화를 실행할지 묻습니다. 원본 팩은 `FOR_AGENTS.md`가 들어 있는 디렉터리입니다. 대상 위치는 `<target-repository>/.cursor/automations/benny/`입니다.

원본 팩 전체를 대상 위치에 병합합니다.

1. 대상 위치가 없으면 생성합니다.
2. 모든 원본 파일을 같은 상대 경로로 복사합니다.
3. 대상 위치에만 있는 파일은 보존합니다. 설치하거나 갱신하는 동안 관련 없는 파일을 절대 삭제하지 않습니다.
4. 사용자가 소유한 구성, 기능 맵, 라우팅 맵은 대상 위치 바깥에 둡니다. 이 파일들을 절대 덮어쓰지 않습니다.
5. 원본에서 관리하는 기존 파일이 다르면 diff를 검토하고, 로컬 수정 사항을 버리지 않도록 병합합니다. 소유권이 모호하면 교체하기 전에 멈추고 묻습니다.
6. 대상 위치에 `FOR_AGENTS.md`, 이 설정 파일, 두 운영 파일, 각 파일의 참고 자료, 템플릿이 들어 있는지 검증합니다.

이 파일을 이미 대상 위치에서 읽고 있다면 복사가 완료된 것으로 간주하고, 계속 진행하기 전에 같은 검증을 실행합니다.

대상 저장소의 `.cursor/settings.json`에 pstack을 추가합니다. 파일이나 `.cursor` 디렉터리가 없으면 생성합니다.

다음 항목을 기존 JSON 또는 JSONC에 병합합니다.

```json
{
	"plugins": {
		"pstack": { "enabled": true }
	}
}
```

관련 없는 최상위 설정과 다른 플러그인 항목은 모두 보존합니다. `plugins.pstack`이 이미 있으면 `enabled` 값만 변경합니다. 파일이 JSONC를 사용한다면 주석과 유효한 JSONC 문법을 보존합니다. 편집한 뒤에는 파일을 검증합니다.

대상 프로젝트를 다시 불러오거나, 그 위치를 루트로 하는 새 에이전트를 시작합니다. 다음 공유 pstack 스킬이 프로젝트 범위에서 해석되는지 검증합니다.

- `how`
- `why`
- `tdd`
- `unslop`
- `principle-separate-before-serializing-shared-state`
- `principle-minimize-reader-load`
- `principle-guard-the-context-window`
- `principle-sequence-verifiable-units`
- `principle-fix-root-causes`
- `principle-prove-it-works`

현재 세션이나 사용자 범위 플러그인에서 불러온 스킬은 인정하지 않습니다. 이 확인은 대상 저장소의 새 에이전트가 프로젝트 설정을 통해 pstack을 받는다는 것을 보여 주어야 합니다.

프로젝트 범위 플러그인 설치를 사용할 수 없거나 공유 의존성 중 하나라도 해석되지 않으면, 멈추고 실패 내용을 설명합니다.

Benny 파일은 `.cursor/automations/benny/`에서 직접 읽습니다. 이 디렉터리를 플러그인 매니페스트에 추가하지 않으며, 그 안의 `SKILL.md` 파일이 슬래시 스킬 목록에 나타나리라고 기대하지 않습니다.

두 자동화 중 하나라도 활성화하기 전에 `.cursor/settings.json`, `.cursor/automations/benny/`, 그리고 참조하는 비밀 정보 없는 구성을 모두 커밋해야 한다고 사용자에게 알립니다. 사용자가 요청하지 않으면 직접 커밋하지 않습니다.

이 확인을 통과하면, 실제로 동작하는 자동화 프롬프트는 커밋된 운영 파일을 안정적인 저장소 상대 경로로 읽을 수 있습니다. 프롬프트에 플러그인 캐시 경로를 넣거나 파일 내용을 복사해 넣어서는 안 됩니다.

## 2. 구성 조정하기

복사된 다음 예시 파일을 엽니다.

- `../../templates/configuration.example.yaml`
- `../reproduce-and-fix-issues/references/feature-map.example.md`

`.cursor/automations/benny/` 바깥에 사용자가 소유하는 사본을 만듭니다. 이 파일들은 팩 파일이 아니라 구성 파일입니다. 위치 예시는 다음과 같습니다.

- 프로젝트 구성(예: `.cursor/benny/configuration.yaml`)
- 프로젝트 기능 맵(예: `.cursor/benny/feature-map.md`)
- 프로젝트 라우팅 맵(예: `.cursor/benny/routing.md`)
- 사용자 구성(예: `~/.config/benny/configuration.yaml`)
- 사용자 기능 맵(예: `~/.config/benny/feature-map.md`)

자동화가 재현할 수 있는 사용자 대상 기능마다 기능 맵 섹션을 하나씩 채웁니다. 내용은 사용자 관점으로 유지합니다. 구현 세부 사항이나 현재 코드 경로를 맵에 고정해 두지 않습니다.

복사된 예시 파일은 편집하지 않습니다. 팩을 갱신할 때 충돌을 검토한 뒤 원본에서 관리하는 파일은 업데이트할 수 있지만, 사용자가 소유한 사본은 절대 건드려서는 안 됩니다.

새로 체크아웃한 자동화가 파일을 읽어야 한다면, 대상 저장소에 커밋된 비밀 정보 없는 파일을 우선 사용합니다. 그렇지 않으면 필요한 값을 풀어 써서 실제 프롬프트에 넣습니다. 내장 `/automate` 스킬이 자동화가 실행되는 저장소에 해당 파일이 커밋되어 있음을 확인한 뒤에만 저장소 파일을 참조합니다.

커밋된 팩 파일과 구성 파일에는 안정적인 저장소 상대 경로를 사용합니다. 실제로 동작하는 자동화에서 플러그인 원본 디렉터리나 플러그인 캐시 경로를 절대 참조하지 않습니다.

## 3. 필수 선택 사항 채우기

다음 항목을 묻거나 확인합니다.

- 원본 Slack 채널 ID
- 선택 사항인 운영 또는 상태 채널 ID
- 저장소 URL과 기본 브랜치
- 분류 담당 신원 또는 Slack 사용자 ID
- 이슈 트래커 유형, 팀, 프로젝트, 레이블, 접수 상태
- 트래커 어댑터 스킬 또는 MCP 액션
- 선택 사항인 라우팅 맵 경로
- 필수 제어 스킬 이름
- 필수 사용자 대상 기능 맵 경로
- 상태 이모지 문자열
- PR URL 형식
- 폴링 예산과 작업량 예산
- 분류, 재현, 코드 작업, 미디어 리뷰에 사용할 모델 슬러그

사용자의 Cursor 모델 선택기나 지원 모델 목록에 사용 가능하다고 표시된 모델 슬러그만 사용합니다. 슬러그를 추측하지 않으며, 비공개 기본값을 그대로 가져오지 않습니다.

원본 채널, 분류 담당 신원, 저장소, 트래커 어댑터, 제어 스킬, 기능 맵은 명시적으로 지정되어야 합니다. 필수 값 중 하나라도 모호한 채로 남으면 설정을 실패로 처리합니다.

최종 자동화 이름, 설명, 프롬프트 shim을 저장하기 전에 pstack의 `unslop` 스킬을 적용합니다.

## 4. 통합 기능 확인하기

분류 자동화에는 다음이 필요합니다.

- 구성된 원본 Slack 채널과 그 스레드에 대한 읽기 권한
- 해당 채널의 스레드 답글 권한
- 보고에 미디어가 포함될 때 첨부 파일 메타데이터와 파일 다운로드 권한
- 구성된 이슈 트래커 어댑터를 통한 검색, 읽기, 생성, 업데이트 권한

재현 자동화에는 다음이 필요합니다.

- 원본 스레드에 대한 읽기 권한
- 원본 채널의 스레드 답글 권한
- 선택 사항으로, 구성된 운영 채널의 게시 및 편집 권한
- 저장소 읽기 권한과 기록 조회 권한
- 초안 PR을 열 수 있는 PR 액션
- 구성된 제어 어댑터 스킬

읽기와 게시에는 구성된 Cursor Slack 액션을 우선 사용합니다. 선택 사항인 `BENNY_SLACK_BOT_TOKEN`은 운영 상태 메시지 하나를 편집하거나 첨부 파일을 다운로드하는 것처럼 좁은 공백을 메우는 데 사용할 수 있습니다. 이 값은 YAML이 아니라 비밀 관리자나 환경에 저장합니다.

문서화되지 않은 통합 엔드포인트는 사용하지 않습니다.

## 5. 라우팅 맵 준비하기

사용자가 경로 재지정이나 담당자 호출을 원한다면 다음을 수행합니다.

1. `../triage-issue-reports/references/routing.example.md`를 `.cursor/automations/benny/` 바깥으로 복사합니다.
2. 모든 자리 표시자를 공개 값이나 조직 내부 값으로 바꿉니다.
3. 담당자 호출은 기본적으로 꺼 둡니다.
4. 구성된 기능 담당자나 회귀를 일으켰을 가능성이 높다고 확인된 작성자에게만 호출을 허용합니다.

라우팅 맵이 구성되지 않았다면, 분류 자동화는 보고를 분류할 수는 있지만 대상 위치나 담당자를 추측해서는 안 됩니다.

## 6. 제어 어댑터 검증하기

`../reproduce-and-fix-issues/references/control-adapter.md`와 사용자가 완성한 기능 맵을 읽습니다.

지정된 스킬이 다음을 할 수 있는지 확인합니다.

- 대상 앱 실행하기
- 매핑된 모든 기능을 실제 UI로 탐색하기
- 선언된 어댑터 액션으로 매핑된 상태를 실행해 보기
- 결과를 강제로 만들지 않고 상태 검사하기
- 스크린샷 캡처하기
- 녹화 시작 및 중지하기
- 자신의 프로세스와 임시 데이터 정리하기

기능이 하나라도 빠져 있으면 재현 자동화를 비활성 상태로 둡니다. 재현 자동화는 수행하지 않은 재현을 수행했다고 주장하지 말고, 안전하게 실패하는 쪽으로 동작해야 합니다.

## 7. 실제 자동화 준비하기

처음 생성하는 것인지, 기존 자동화를 구성하는 것인지 묻습니다.

어느 경우든 복사된 팩의 `../../FOR_AGENTS.md`를 사용자 의도를 파악하는 주요 출처로 읽습니다. 이 파일을 통해 두 트리거, 도구, 지침, 결과, 공유 규칙을 이해합니다.

### 처음 생성하는 경우

자동화는 한 번에 하나씩 생성합니다.

각 자동화마다 다음을 수행합니다.

1. 일치하는 복사된 프롬프트 템플릿을 보조 내부 자료로 읽습니다.
2. `FOR_AGENTS.md`, 완성된 Benny 구성, 템플릿의 의도를 바탕으로 완전한 자연어 요청을 작성합니다.
3. 실제 프롬프트가 `.cursor/automations/benny/` 아래에 커밋된 정확한 운영 파일을 읽고 따르도록 지시합니다.
4. 플러그인 원본 경로나 캐시 경로가 아니라 안정적인 저장소 상대 경로를 사용합니다. 운영 파일 내용을 실제 프롬프트에 복사하지 않습니다.
5. 내장 `automate` 스킬을 읽고 따릅니다.
6. `automate`가 Slack 채널, 저장소, 연결된 통합을 찾도록 맡깁니다.
7. `automate`가 복사된 팩과 참조하는 구성 파일이 자동화가 실행될 저장소와 같은 저장소에 커밋되어 있는지 확인하도록 맡깁니다.
8. `automate`가 초안 표를 보여 주고, 승인을 받고, 준비 여부를 묻고, Automations 편집기를 열도록 맡깁니다.
9. 다음 자동화를 시작하기 전에 이 자동화의 편집기 인계를 마칩니다.

구성에서 값을 채운 다음의 완전한 분류 의도를 `automate`에 전달합니다.

- 이름은 `benny-triage`입니다.
- 모든 실행에서 `.cursor/automations/benny/skills/triage-issue-reports/SKILL.md`를 읽고 따릅니다.
- 구성된 원본 Slack 채널에 새 최상위 보고가 올라올 때마다 트리거됩니다.
- 트리거한 스레드를 읽고, 그 스레드 안에서만 답글을 답니다.
- 구성된 이슈 트래커 통합을 사용합니다.
- 분류하고, 증거를 검사하고, 원인을 추적하고, 중복을 제거하고, 명확한 새 버그만 생성합니다.
- 스레드 전용 판정 하나를 구성된 `[benny:bug]`, `[benny:performance]`, `[benny:other]` 마커 중 하나와 선택 사항인 트래커 URL로 마무리합니다.
- 원본 채널에 루트 메시지를 절대 게시하지 않습니다.

분류 자동화의 편집기 인계가 끝나면, 다음의 완전한 재현 및 수정 의도를 `automate`에 전달합니다.

- 이름은 `benny-reproduce`입니다.
- 모든 실행에서 `.cursor/automations/benny/skills/reproduce-and-fix-issues/SKILL.md`를 읽고 따릅니다.
- 구성된 원본 Slack 채널의 같은 새 최상위 보고에 트리거됩니다.
- 구성된 저장소와 기본 브랜치를 사용합니다.
- 원본 스레드를 읽고, 그 스레드 안에서만 답글을 답니다.
- PR 생성과, 구성된 트래커, 제어 어댑터, 기능 맵 요구 사항을 포함합니다. `automate`가 같은 저장소에 커밋된 적격 파일을 확인하지 않는 한, 매핑된 사용자 경로와 상태는 풀어 써서 넣습니다.
- 행동하기 전에 신뢰할 수 있는 분류 마커를 기다립니다.
- 매핑된 실제 UI를 통해 정확한 증상을 두 번 재현하고 증거를 캡처합니다.
- 기존 수정 사항이 있으면 그 위에 새로 작성하지 않고 검증합니다.
- 재현이 확인된 뒤에만 범위가 제한된 선택적 수정을 시도하고, 증명과 검사를 통과하면 초안 PR을 엽니다.
- 원본 채널에 루트 메시지를 절대 게시하지 않습니다.

`automate`가 수행하는 Slack, 저장소, 통합, 완전성, 인증, 초안 리뷰, 승인, 준비 여부, 편집기 인계 작업을 중복해서 수행하지 않습니다.

### 기존 자동화인 경우

내장 `automate` 스킬은 생성 전용입니다. 기존 자동화를 검색하거나, 검사하거나, 업데이트하는 데 이 스킬을 사용하지 않습니다.

구성, 라우팅, 제어 어댑터, 기능 맵 검증을 마칩니다. 그런 다음 사용자에게 다음과 같은 간결한 편집기 체크리스트를 제공합니다.

기존 분류 자동화에서는 다음을 업데이트합니다.

- 이름과 설명
- `.cursor/automations/benny/skills/triage-issue-reports/SKILL.md`를 읽으라는 직접 지시
- 새 최상위 Slack 보고 트리거와 원본 채널
- Slack 스레드 읽기 및 답글 기능
- 이슈 트래커 통합
- 풀어 쓴 분류 지침, 스레드 전용 규칙, Benny 판정 마커

기존 재현 자동화에서는 다음을 업데이트합니다.

- 이름과 설명
- `.cursor/automations/benny/skills/reproduce-and-fix-issues/SKILL.md`를 읽으라는 직접 지시
- 일치하는 Slack 트리거와 원본 채널
- 저장소와 기본 브랜치
- Slack 스레드 읽기 및 답글 기능
- PR 액션
- 트래커, 제어 어댑터, 기능 맵 요구 사항
- 풀어 쓴 마커 대기, 증거, 검증, 범위 제한 수정 지침

사용자에게 각 기존 자동화를 해당 Automations 편집기에서 직접 업데이트해 달라고 요청합니다. 대체 자동화나 중복 자동화를 만들지 않습니다.

### 생성 경계

자동화 백엔드 서비스나 백엔드 자동화 도구를 절대 직접 호출하지 않습니다. 초안 필드를 담은 브라우저 URL을 절대 사용하지 않습니다. Cursor 프로토콜 딥 링크를 절대 만들거나 열지 않습니다. 새 자동화를 마무리하는 유일한 경로는 내장 `automate` 스킬이 리뷰를 거쳐 수행하는 Automations 편집기 인계입니다.

편집기에서 저장한 뒤 스레드 안전성 테스트를 통과하기 전에는 두 자동화 중 어느 것도 활성화하지 않습니다.

## 8. 스레드 안전성 테스트하기

테스트 채널이나 무해한 테스트 보고를 사용합니다.

테스트하기 전에, 대상 저장소의 `.cursor/settings.json`, `.cursor/automations/benny/`, 참조하는 비밀 정보 없는 모든 구성 파일이 자동화 체크아웃에 사용되는 브랜치에 커밋되어 있는지 확인합니다. 두 실제 프롬프트가 각자 커밋된 정확한 운영 파일을 가리키는지 확인합니다. 확인 중 하나라도 실패하면 멈춥니다. 사용자에게 아직 자동화를 활성화할 수 없다고 알립니다.

다음을 검증합니다.

1. 분류 자동화가 루트 `thread_ts`를 저장하고 정확히 하나의 판정을 답글로 게시합니다.
2. 판정에 구성된 마커가 하나 들어 있습니다.
3. 재현 자동화는 구성된 분류 담당 신원이 남긴 마커만 받아들입니다.
4. 재현 자동화는 변경할 수 없는 동일한 원본 좌표를 유지합니다.
5. 원본 채널에 루트 메시지가 나타나지 않습니다.
6. 위임된 작업자는 어떤 Slack 쓰기 액션도 사용할 수 없습니다.
7. 좌표가 누락되었거나, 부모 메시지가 삭제되었거나, 사전 점검이 실패하면 게시물과 트래커 이슈가 생성되지 않습니다.

일곱 가지 확인을 모두 통과한 뒤에만 일반 트래픽을 활성화합니다.
